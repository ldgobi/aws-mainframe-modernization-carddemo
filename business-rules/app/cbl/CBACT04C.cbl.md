# CBACT04C.cbl: Interest Calculator Program

## Overview
The `CBACT04C.cbl` file is a COBOL batch program designed to calculate and process interest for accounts based on transaction category balances. It reads data from multiple input files, performs calculations, and updates account records with the computed interest. The program also generates transaction records for the calculated interest and writes them to an output file.

This program is part of the `CardDemo` application and plays a critical role in ensuring accurate interest calculations for customer accounts. It processes transaction category balances, retrieves account and cross-reference data, determines applicable interest rates, computes interest amounts, and updates account balances accordingly.

The program is structured to handle errors gracefully, ensuring data integrity and providing detailed error messages when issues occur. It also includes provisions for handling default interest rates when specific disclosure group records are missing.

## Business Rules:
### File Operations
1. **Input Files**:
   - **TCATBAL-FILE**: Contains transaction category balances. Records are processed sequentially.
   - **XREF-FILE**: Provides cross-reference data for accounts and cards. Accessed randomly using account ID or card number.
   - **ACCOUNT-FILE**: Stores account details. Accessed randomly using account ID.
   - **DISCGRP-FILE**: Contains disclosure group data, including interest rates. Accessed randomly using a composite key of account group ID, transaction type code, and transaction category code.

2. **Output File**:
   - **TRANSACT-FILE**: Stores transaction records for computed interest. Written sequentially.

3. **File Status Handling**:
   - Each file operation checks the file status. If the status is not '00' (success), the program logs an error message, displays the file status, and terminates execution.

### Processing Logic
1. **Initialization**:
   - Open all input and output files.
   - Initialize working storage variables, including counters and flags.

2. **Main Processing Loop**:
   - Process records from `TCATBAL-FILE` sequentially until the end of the file.
   - For each record:
     - Check if the account ID has changed since the last record.
       - If yes, update the previous account's balance with the total computed interest and reset the total interest accumulator.
       - Retrieve account data from `ACCOUNT-FILE` and cross-reference data from `XREF-FILE`.
     - Retrieve the applicable interest rate from `DISCGRP-FILE` using the account group ID, transaction type code, and transaction category code.
       - If the disclosure group record is missing, use a default group code to retrieve a default interest rate.
     - Compute the monthly interest using the formula:
       ```
       Monthly Interest = (Transaction Category Balance * Interest Rate) / 1200
       ```
       - Add the computed interest to the total interest accumulator.
     - Generate a transaction record for the computed interest and write it to `TRANSACT-FILE`.

3. **Account Updates**:
   - At the end of processing for an account, update the account's current balance in `ACCOUNT-FILE` to reflect the total computed interest. Reset cycle credit and debit balances to zero.

4. **Error Handling**:
   - If any file operation fails, display an error message, log the file status, and terminate the program.

5. **Closing Files**:
   - Close all input and output files at the end of processing.

### Detailed Calculations
1. **Interest Calculation**:
   - The interest is calculated for each transaction category balance using the formula:
     ```
     Monthly Interest = (Transaction Category Balance * Interest Rate) / 1200
     ```
   - The result is added to the total interest accumulator for the account.

2. **Transaction Record Generation**:
   - A unique transaction ID is generated by concatenating the processing date and a transaction ID suffix.
   - The transaction record includes:
     - Transaction type code: '01'
     - Transaction category code: '05'
     - Source: 'System'
     - Description: 'Int. for a/c <Account ID>'
     - Amount: Computed monthly interest
     - Card number: Retrieved from `XREF-FILE`
     - Timestamps: Current date and time in DB2 format.

3. **Account Balance Update**:
   - The total computed interest is added to the account's current balance.
   - Cycle credit and debit balances are reset to zero.

### Error Scenarios
1. **File Open Errors**:
   - If any file fails to open, the program logs the error, displays the file status, and terminates.

2. **File Read Errors**:
   - If a record cannot be read, the program logs the error, displays the file status, and terminates.

3. **File Write Errors**:
   - If a record cannot be written, the program logs the error, displays the file status, and terminates.

4. **Missing Disclosure Group Records**:
   - If a disclosure group record is missing, the program attempts to retrieve a default interest rate using a default group code.

### Data Fields and Structures
1. **Transaction Category Balance Record (TCATBAL-FILE)**:
   - `FD-TRANCAT-ACCT-ID`: Account ID (11 digits)
   - `FD-TRANCAT-TYPE-CD`: Transaction type code (2 characters)
   - `FD-TRANCAT-CD`: Transaction category code (4 digits)
   - `FD-FD-TRAN-CAT-DATA`: Additional data (33 characters)

2. **Cross-Reference Record (XREF-FILE)**:
   - `FD-XREF-CARD-NUM`: Card number (16 characters)
   - `FD-XREF-CUST-NUM`: Customer number (9 digits)
   - `FD-XREF-ACCT-ID`: Account ID (11 digits)

3. **Disclosure Group Record (DISCGRP-FILE)**:
   - `FD-DIS-ACCT-GROUP-ID`: Account group ID (10 characters)
   - `FD-DIS-TRAN-TYPE-CD`: Transaction type code (2 characters)
   - `FD-DIS-TRAN-CAT-CD`: Transaction category code (4 digits)
   - `FD-DISCGRP-DATA`: Additional data (34 characters)

4. **Account Record (ACCOUNT-FILE)**:
   - `FD-ACCT-ID`: Account ID (11 digits)
   - `FD-ACCT-DATA`: Account data (289 characters)

5. **Transaction Record (TRANSACT-FILE)**:
   - `FD-TRANS-ID`: Transaction ID (16 characters)
   - `FD-ACCT-DATA`: Transaction data (334 characters)

  - Placeholder logic exists for computing fees, but it is not yet implemented.

This program ensures accurate interest calculations and updates for customer accounts. It handles various scenarios, including missing disclosure group records, and provides detailed error handling to maintain data integrity. The program's modular structure allows for easy maintenance and future enhancements, such as implementing fee calculations.
